build of ONNX Runtime (C/C++/Python/C#), see the <a href="/docs/execution-providers/WebGPU-ExecutionProvider.html">WebGPU Execution Provider</a> page instead.</p> </blockquote> <h2 class="no_toc" id="contents"> <a href="#contents" class="anchor-heading" aria-labelledby="contents"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Contents </h2> <ul id="markdown-toc"> <li><a href="#basics" id="markdown-toc-basics">Basics</a> <ul> <li><a href="#what-is-webgpu-should-i-use-it" id="markdown-toc-what-is-webgpu-should-i-use-it">What is WebGPU? Should I use it? </h3> <p>WebGPU is a new web standard for general purpose GPU compute and graphics. It is designed to be a low-level API, based on D3D12, Vulkan and Metal, and is designed to be used in the browser. It is designed to be more efficient and performant than WebGL, and is designed to be used for machine learning, graphics, and other compute tasks.</p> <p>WebGPU is available out-of-box in latest versions of Chrome and Edge on Windows, macOS, Android and ChromeOS. It is also available in Firefox behind a flag and Safari Technology Preview. Check <a href="https://webgpu.io/status/">WebGPU status</a> for the latest information.</p> <p>If you are using ONNX Runtime Web for inferencing very lightweight models in you web application, and you want to have a small binary size, you can keep using the default WebAssembly (WASM) execution provider. If you want to run more compute intensive models, or you want to take advantage of the GPU in the client’s device, you can use the WebGPU execution provider.</p> <h3 id="how-to-use-webgpu-ep-in-onnx-runtime-web"> <a href="#how-to-use-webgpu-ep-in-onnx-runtime-web" class="anchor-heading" aria-labelledby="how-to-use-webgpu-ep-in-onnx-runtime-web"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> How to use WebGPU EP in ONNX Runtime Web </h3> <p>This section assumes you have already set up your web application with ONNX Runtime Web. If you haven’t, you can follow the <a href="/docs/get-started/with-javascript/web.html">Get Started</a> for some basic info.</p> <p>To use WebGPU EP, you just need to make 2 small changes:</p> <ol> <li> <p>Update your import statement:</p> <ul> <li>For HTML script tag, change <code class="language-plaintext highlighter-rouge">ort.min.js</code> to <code class="language-plaintext highlighter-rouge">ort.webgpu.min.js</code>: <div class="language-html highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="nt">&lt;script </span><span class="na">src=</span><span class="s">"https://example.com/path/ort.webgpu.min.js"</span><span class="nt">&gt;&lt;/script&gt;</span>
</code></pre></div> </div> </li> <li>For JavaScript import statement, change <code class="language-plaintext highlighter-rouge">onnxruntime-web</code> to <code class="language-plaintext highlighter-rouge">onnxruntime-web/webgpu</code>: <div class="language-js highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="k">import</span> <span class="o">*</span> <span class="k">as</span> <span class="nx">ort</span> <span class="k">from</span> <span class="dl">'</span><span class="s1">onnxruntime-web/webgpu</span><span class="dl">'</span><span class="p">;</span>
</code></pre></div> </div> </li> </ul> <p>See <a href="https://github.com/microsoft/onnxruntime-inference-examples/tree/main/js/importing_onnxruntime-web#conditional-importing">Conditional Importing</a> for details.</p> </li> <li> <p>Specify ‘webgpu’ EP explicitly in session options:</p> <div class="language-js highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kd">const</span> <span class="nx">session</span> <span class="o">=</span> <span class="k">await</span> <span class="nx">ort</span><span class="p">.</span><span class="nx">InferenceSession</span><span class="p">.</span><span class="nx">create</span><span class="p">(</span><span class="nx">modelPath</span><span class="p">,</span> <span class="p">{</span> <span class="p">...,</span> <span class="na">executionProviders</span><span class="p">:</span> <span class="p">[</span><span class="dl">'</span><span class="s1">webgpu</span><span class="dl">'</span><span class="p">]</span> <span class="p">});</span>
</code></pre></div> </div> </li> </ol> <p>You might also consider installing the latest nightly build version of ONNX Runtime Web (onnxruntime-web@dev) to benefit from the latest features and improvements.</p> <h2 id="webgpu-ep-features"> <a href="#webgpu-ep-features" class="anchor-heading" aria-labelledby="webgpu-ep-features"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> WebGPU EP features </h2> <p>ONNX Runtime Web offers the following features which may be helpful to use with WebGPU EP:</p> <h3 id="graph-capture"> <a href="#graph-capture" class="anchor-heading" aria-labelledby="graph-capture"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Graph Capture </h3> <p>You can try the graph capture feature if your model has static shapes and all its computing kernels are running on WebGPU EP. This feature may potentially improve the performance of your model.</p> <p>See <a href="/docs/tutorials/web/env-flags-and-session-options.html#enablegraphcapture">Graph Capture</a> for more details.</p> <h3 id="using-ortenvwebgpu-flags"> <a href="#using-ortenvwebgpu-flags" class="anchor-heading" aria-labelledby="using-ortenvwebgpu-flags"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Using <code class="language-plaintext highlighter-rouge">ort.env.webgpu</code> flags </h3> <p>See <a href="/docs/tutorials/web/env-flags-and-session-options.html#envwebgpu"><code class="language-plaintext highlighter-rouge">env.webgpu</code></a> for more details.</p> <h2 id="keep-tensor-data-on-gpu-io-binding"> <a href="#keep-tensor-data-on-gpu-io-binding" class="anchor-heading" aria-labelledby="keep-tensor-data-on-gpu-io-binding"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Keep tensor data on GPU (IO binding) </h2> <p>By default, a model’s inputs and outputs are tensors that hold data in CPU memory. When you run a session with WebGPU EP, the data is copied to GPU memory, and the results are copied back to CPU memory. If you get your input data from a GPU-based source, or you want to keep the output data on GPU for further processing, you can use IO binding to keep the data on GPU. This will be especially helpful when running transformer based models, which usually runs a single model multiple times with previous output as the next input.</p> <p>For model input, if your input data is a WebGPU storage buffer, you can <a href="#create-input-tensor-from-a-gpu-buffer">create a GPU tensor and use it as input tensor</a>.</p> <p>For model output, there are 2 ways to use the IO binding feature:</p> <ul> <li><a href="#use-pre-allocated-gpu-tensors">Use pre-allocated GPU tensors</a></li> <li><a href="#specify-the-output-data-location">Specify the output data location</a></li> </ul> <p>Please also check the following topics:</p> <ul> <li><a href="#zero-sized-tensors">Zero-sized tensors</a></li> <li><a href="#gpu-tensor-life-cycle-management">GPU tensor life cycle management</a></li> </ul> <h3 id="create-input-tensor-from-a-gpu-buffer"> <a href="#create-input-tensor-from-a-gpu-buffer" class="anchor-heading" aria-labelledby="create-input-tensor-from-a-gpu-buffer"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Create input tensor from a GPU buffer </h3> <p>If your input data is a WebGPU storage buffer, you can create a GPU tensor and use it as input tensor:</p> <div class="language-js highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kd">const</span> <span class="nx">inputTensor</span> <span class="o">=</span> <span class="nx">ort</span><span class="p">.</span><span class="nx">Tensor</span><span class="p">.</span><span class="nx">fromGpuBuffer</span><span class="p">(</span><span class="nx">inputGpuBuffer</span><span class="p">,</span> <span class="p">{</span>
  <span class="na">dataType</span><span class="p">:</span> <span class="dl">'</span><span class="s1">float32</span><span class="dl">'</span><span class="p">,</span>
  <span class="na">dims</span><span class="p">:</span> <span class="p">[</span><span class="mi">1</span><span class="p">,</span> <span class="mi">3</span><span class="p">,</span> <span class="mi">224</span><span class="p">,</span> <span class="mi">224</span><span class="p">]</span>
<span class="p">});</span>

</code></pre></div></div> <p>Use this tensor as model inputs(feeds) so that the input data will be kept on GPU.</p> <h3 id="use-pre-allocated-gpu-tensors"> <a href="#use-pre-allocated-gpu-tensors" class="anchor-heading" aria-labelledby="use-pre-allocated-gpu-tensors"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Use pre-allocated GPU tensors </h3> <p>If you know the output shape in advance, you can create a GPU tensor and use it as output tensor:</p> <div class="language-js highlighter-rouge"><div class="highlight"><pre class="highlight"><code>
<span class="c1">// Create a pre-allocated buffer and the corresponding tensor. Assuming that the output shape is [10, 1000].</span>
<span class="kd">const</span> <span class="nx">bufferSize</span> <span class="o">=</span> <span class="p">(</span><span class="mi">10</span> <span class="o">*</span> <span class="mi">1000</span><span class="p">)</span> <span class="cm">/* number of elements */</span> <span class="o">*</span> <span class="mi">4</span> <span class="cm">/* bytes per element */</span><span class="p">;</span>
<span class="kd">const</span> <span class="nx">device</span> <span class="o">=</span> <span class="nx">ort</span><span class="p">.</span><span class="nx">env</span><span class="p">.</span><span class="nx">webgpu</span><span class="p">.</span><span class="nx">device</span><span class="p">;</span>
<span class="kd">const</span> <span class="nx">myPreAllocatedBuffer</span> <span class="o">=</span> <span class="nx">device</span><span class="p">.</span><span class="nx">createBuffer</span><span class="p">({</span>
    <span class="na">usage</span><span class="p">:</span> <span class="nx">GPUBufferUsage</span><span class="p">.</span><span class="nx">COPY_SRC</span> <span class="o">|</span> <span class="nx">GPUBufferUsage</span><span class="p">.</span><span class="nx">COPY_DST</span> <span class="o">|</span> <span class="nx">GPUBufferUsage</span><span class="p">.</span><span class="nx">STORAGE</span><span class="p">,</span>
    <span class="na">size</span><span class="p">:</span> <span class="nb">Math</span><span class="p">.</span><span class="nx">ceil</span><span class="p">(</span><span class="nx">bufferSize</span> <span class="o">/</span> <span class="mi">16</span><span class="p">)</span> <span class="o">*</span> <span class="mi">16</span> <span class="cm">/* align to 16 bytes */</span>
<span class="p">});</span>

<span class="kd">const</span> <span class="nx">myPreAllocatedOutputTensor</span> <span class="o">=</span> <span class="nx">ort</span><span class="p">.</span><span class="nx">Tensor</span><span class="p">.</span><span class="nx">fromGpuBuffer</span><span class="p">(</span><span class="nx">myPreAllocatedBuffer</span><span class="p">,</span> <span class="p">{</span>
  <span class="na">dataType</span><span class="p">:</span> <span class="dl">'</span><span class="s1">float32</span><span class="dl">'</span><span class="p">,</span>
  <span class="na">dims</span><span class="p">:</span> <span class="p">[</span><span class="mi">10</span><span class="p">,</span> <span class="mi">1000</span><span class="p">]</span>
<span class="p">});</span>

<span class="c1">// ...</span>

<span class="c1">// Run the session with fetches</span>
<span class="kd">const</span> <span class="nx">feeds</span> <span class="o">=</span> <span class="p">{</span> <span class="dl">'</span><span class="s1">input_0</span><span class="dl">'</span><span class="p">:</span> <span class="nx">myInputTensor</span> <span class="p">};</span>
<span class="kd">const</span> <span class="nx">fetches</span> <span class="o">=</span> <span class="p">{</span> <span class="dl">'</span><span class="s1">output_0</span><span class="dl">'</span><span class="p">:</span> <span class="nx">myPreAllocatedOutputTensor</span> <span class="p">};</span>
<span class="kd">const</span> <span class="nx">results</span> <span class="o">=</span> <span class="k">await</span> <span class="nx">mySession</span><span class="p">.</span><span class="nx">run</span><span class="p">(</span><span class="nx">feeds</span><span class="p">,</span> <span class="nx">fetches</span><span class="p">);</span>

</code></pre></div></div> <p>By specifying the output tensor in the fetches, ONNX Runtime Web will use the pre-allocated buffer as the output buffer. If there is a shape mismatch, the <code class="language-plaintext highlighter-rouge">run()</code> call will fail.</p> <h3 id="specify-the-output-data-location"> <a href="#specify-the-output-data-location" class="anchor-heading" aria-labelledby="specify-the-output-data-location"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Specify the output data location </h3> <p>If you don’t want to use pre-allocated GPU tensors for outputs, you can also specify the output data location in the session options:</p> <div class="language-js highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kd">const</span> <span class="nx">mySessionOptions1</span> <span class="o">=</span> <span class="p">{</span>
  <span class="p">...,</span>
  <span class="c1">// keep all output data on GPU</span>
  <span class="na">preferredOutputLocation</span><span class="p">:</span> <span class="dl">'</span><span class="s1">gpu-buffer</span><span class="dl">'</span>
<span class="p">};</span>

<span class="kd">const</span> <span class="nx">mySessionOptions2</span> <span class="o">=</span> <span class="p">{</span>
  <span class="p">...,</span>
  <span class="c1">// alternatively, you can specify the output location for each output tensor</span>
  <span class="na">preferredOutputLocation</span><span class="p">:</span> <span class="p">{</span>
    <span class="dl">'</span><span class="s1">output_0</span><span class="dl">'</span><span class="p">:</span> <span class="dl">'</span><span class="s1">cpu</span><span class="dl">'</span><span class="p">,</span>         <span class="c1">// keep output_0 on CPU. This is the default behavior.</span>
    <span class="dl">'</span><span class="s1">output_1</span><span class="dl">'</span><span class="p">:</span> <span class="dl">'</span><span class="s1">gpu-buffer</span><span class="dl">'</span>   <span class="c1">// keep output_1 on GPU buffer</span>
  <span class="p">}</span>
<span class="p">};</span>
</code></pre></div></div> <p>By specifying the config <code class="language-plaintext highlighter-rouge">preferredOutputLocation</code>, ONNX Runtime Web will keep the output data on the specified device.</p> <p>See <a href="https://onnxruntime.ai/docs/api/js/interfaces/InferenceSession.SessionOptions.html#preferredOutputLocation">API reference: preferredOutputLocation</a> for more details.</p> <h2 id="notes"> <a href="#notes" class="anchor-heading" aria-labelledby="notes"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Notes </h2> <h3 id="zero-sized-tensors"> <a href="#zero-sized-tensors" class="anchor-heading" aria-labelledby="zero-sized-tensors"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> Zero-sized tensors </h3> <p>If a tensor’s shape contains 1 or more dimensions with size 0, the tensor is considered as a zero-sized tensor. Zero-sized tensors do not have any data, so the data location is not applied. ONNX Runtime Web always treats zero-sized tensors as CPU tensors. To create a zero-sized tensor, you can use the following code:</p> <div class="language-js highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="kd">const</span> <span class="nx">zeroSizedTensor</span> <span class="o">=</span> <span class="k">new</span> <span class="nx">ort</span><span class="p">.</span><span class="nx">Tensor</span><span class="p">(</span><span class="dl">'</span><span class="s1">float32</span><span class="dl">'</span><span class="p">,</span> <span class="p">[],</span> <span class="p">[</span><span class="mi">3</span><span class="p">,</span> <span class="mi">256</span><span class="p">,</span> <span class="mi">0</span><span class="p">,</span> <span class="mi">64</span><span class="p">]);</span>
</code></pre></div></div> <h3 id="gpu-tensor-life-cycle-management"> <a href="#gpu-tensor-life-cycle-management" class="anchor-heading" aria-labelledby="gpu-tensor-life-cycle-management"><svg viewBox="0 0 16 16" aria-hidden="true"><use xlink:href="#svg-link"></use></svg></a> GPU tensor life cycle management </h3> <p>It is important to understand how the underlying GPU buffer is managed so that you can avoid memory leaks and improve buffer usage efficiency.</p> <p>A GPU tensor is created either by user code or by ONNX Runtime Web as model’s output.</p> <ul> <li> <p>When it is created by user code, it is always created with an existing GPU buffer using <code class="language-plaintext highlighter-rouge">Tensor.fromGpuBuffer()</code>. In this case, the tensor does not “own” the GPU buffer.</p> <ul> <li>It is user’s responsibility to make sure the underlying buffer is valid during the inference, and call <code class="language-plaintext highlighter-rouge">buffer.destroy()</code> to dispose the buffer when it is no longer needed.</li> <li>Avoid calling <code class="language-plaintext highlighter-rouge">tensor.getData()</code> and <code class="language-plaintext highlighter-rouge">tensor.dispose()</code>. Use the GPU buffer directly.</li> <li>Using a GPU tensor with a destroyed GPU buffer will cause the session run to fail.</li> </ul> </li> <li> <p>When it is created by ONNX Runtime Web as model’s output (not a pre-allocated GPU tensor), the tensor “owns” the buffer.</p> <ul> <li>You don’t need to worry about the case that the buffer is destroyed before the tensor is used.</li> <li>Call <code class="language-plaintext highlighter-rouge">tensor.getData()</code> to download the data from the GPU buffer to CPU and get the data as a typed array.</li> <li>Call <code class="language-plaintext highlighter-rouge">tensor.dispose()</code> explicitly to destroy the underlying GPU buffer when it is no longer needed.</li> </ul> </li> </ul> </main> <hr> <footer> <p class="text-small text-grey-dk-100 mb-0">For documentation questions, please <a href="https://github.com/microsoft/onnxruntime/issues/new?assignees=&labels=documentation&projects=&template=02-documentation.yml&title=%5BDocumentation%5D+" target="_blank">file an issue</a>.</p> <div class="d-flex mt-2"> <p class="text-small mb-0"> <a href="https://github.com/microsoft/onnxruntime/tree/gh-pages/docs/tutorials/web/ep-webgpu.md" id="edit-this-page">Edit this page on GitHub</a> </p> </div> <div class="d-md-none mt-4 fs-2"> This site uses <a href="https://github.com/just-the-docs/just-the-docs">Just the Docs</a>, a documentation theme for Jekyll. </div> </footer> </div> </div> <div class="search-overlay"></div> </div> </body> </html>
