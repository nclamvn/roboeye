# TIP-64B4 — Independent recognition / preprocessing scan

2026-10-11 · Core Builder · initially read-only scan; subsequent Contractor-approved C06 repair only.

## Decision in brief

The fan miss and the phone/remote confusion are **not one UI-color defect**. The shipped detector cannot name a fan because that class is absent. Phone/remote is a supported-class semantic error whose actual cause remains unmeasured. The scan identified a narrower code defect: changing those two labels could retain an obsolete contradictory coast box. C06 repairs that duplicate artifact, **not the model's wrong label**.

Do not relabel remote as phone, force a fan class, silently lower confidence, hold expired metres, or promise recognition quality from a newer model's name. The next useful step is a small local recognition comparison with actual phone/remote examples, correct image orientation and full competing-label evidence, followed by a separately gated model/data decision.

### What the resize finding does and does not prove

For source widthW and heightH, stretch factors are416/W and416/H; relative shape distortion isH/W. A 4:3 raw frame stretched to square changes relative axes by4/3. The existing screenshot-smoke dimensions868×1887 have ratio≈2.174; those dimensions include screenshot/UI context and must **not** be treated as the native ARKit frame dimensions. No actual raw phone-confusion frame or top-k scores were provided during this scan.

An aspect-preserving `.scaleFit` experiment may preserve phone silhouette, but it reduces the occupied input area and introduces padding; tiny phones can become even smaller. Center-crop can remove useful edge objects. Verify model training expectations and the exact Vision/explicit-resize box mapping before changing anything. A caller-provided letterboxed image must have its transform undone exactly once; never feed letterbox coordinates directly into LiDAR sampling. Current raw normalized / RGB-pixel depth geometry remains untouched.

### Tracking is not a semantic reclassifier

Between detector passes, `VNTrackObjectRequest` yields geometric boxes and confidence (`ObjectPipeline.swift:179–198`); the previous label is retained by `updateTrackedBoxes`. The next detector can change the class. Geometry tracking cannot convert a wrong remote prediction into a correctly identified phone. Detection spacing is bounded/adaptive (normally0.2s, thermal base0.4s, work-driven cap1s); a label observed between such passes is not a fresh semantic classification on every rendered frame.

## Approved C06 repair and boundary

Only high-overlap **canonical `cell phone`↔`remote`** contradictory hypotheses are affected. Existing duplicate IoU>0.75 is reused. Stronger raw detection score wins; equal different-class scores use a general canonical-label lexicographic order, never a special preference for phone. Existing equal-score same-class observation order is preserved. Only an unmatched obsolete contradictory coast is retired when a current box occupies essentially the same geometry. A new identity always awaits its own same-frame depth and cannot inherit metres.

Separate or sub-boundary phone/remote boxes remain separate. Person/phone, book/phone, chair/bottle and other legitimate nested classes are not broad cross-class-NMS targets. No model, confidence threshold, preprocessing, estimator, metric TTL, v1 contract or automatic recording policy changed. This is explicitly a presentation/identity-conflict repair, **not measured semantic recall improvement**.

Added six tracker regressions: phone→remote, remote→phone, stronger-score concurrent hypotheses under permutations, exact-score deterministic tie, separated/sub-boundary pair, and nested unrelated-class preservation. Application parsing passed; no Xcode/device/model command was performed by this Builder. A read-only Node inspection of existing compiled-model JSON confirmed the vocabulary; no model inference/build/download was used for that inspection.

## Small measurable next experiment

1. **Actual local inputs.** Ask the user for consenting photos or short clips of the physical smartphone misread as remote, a real remote, and negative rectangular objects. Include screen on/off, front/back, hand occlusion, portrait/landscape, edge/center, distance and lighting. Avoid unnecessary people/private displays; no automatic upload. Keep complete clips/objects disjoint between development and holdout. Fan belongs in a separately tagged out-of-vocabulary set, not in baseline80-class recall.
2. **Correct the evaluation apparatus first.** A later approved QA change should honor EXIF, record raw dimensions/orientation, retain top3–5 labels with both confidence components and their products, and pin artifact hash/thresholds/preprocessing. Bounded diagnostics do not require storing every camera frame. Record predictions before and after tracking separately to avoid confusing class error with track persistence.
3. **One-variable preprocessing comparison.** Run identical full-resolution inputs through shipping scaleFill and a precisely specified aspect-preserving fit/letterbox experiment. Keep model/threshold/NMS fixed. Test corner/rotation/box roundtrips at all four cardinal rotations; ensure supports still refer to same raw RGB/depth coordinates. Report phone→remote and remote→phone confusion, missed detections, duplicate count, recall/precision at matched boxes, class-margin distribution and box area in model pixels. Do not claim a winner from one successful frame.
4. **Calibrate abstention, not invented correction.** If alternatives demonstrate near-ties, evaluate a bounded uncertain-class presentation policy against development data and freeze it before holdout. A wrong high-confidence prediction may not be fixed by any margin. Do not suppress difficult examples to make recall look better or call unknown/free space safe. Keep metre quality/freshness independent of semantic confidence.
5. **Native candidate gate.** Compare the existing artifact with at most one permissively licensed small detector chosen by the Contractor. Verify a real Core ML artifact, tensor/decoder/NMS/vocabulary contracts, code **and** weight/data license, input transform and offline size. The RF-DETR/YOLOX evaluation lanes discussed in B3 still require conversion/phone validation and still lack fan if using only80-class weights. Fan requires verified wider-vocabulary weights or a deliberately trained additional class; wide/open-vocabulary inference and scene-language models are not automatically efficient native-frame detectors.
6. **Promotion requires phone evidence.** Run on the demo iPhone, report inference and capture→ready P50/P95 separately, drops/visual gaps/label switches, memory and30-minute heat behavior. Maintain current 300ms range freshness and background/reset tests. Pair detection improvement with independently measured surface error/refusal coverage; box/class success alone does not prove safe navigation or reliable all-object range.
